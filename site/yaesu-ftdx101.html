The Yaesu FTDX101 on HF: one cable, one menu setting

The FTDX101 receives fine, and then it never transmits: NeoAPRS says it is sending and the radio stays on receive. The cause is one menu item on the radio. Change it, and the one USB cable between the radio and the computer is all a Mercury radio on HF needs: no interface box and no audio leads.

What the cable brings

The radio's USB socket gives the computer a sound card and two serial ports.

A sound cardShown as "USB AUDIO CODEC": the radio's receive and transmit audio
Two serial portsYaesu calls the first the Enhanced COM Port, for CAT, and the second the Standard COM Port, for keying

In NeoAPRS

  1. Settings → Radio → Add radio: Sound card under Mercury (DATAC3), then Add.
  2. Sound card: USB AUDIO CODEC.
  3. Keying: RTS on the second of the radio's two serial ports. On Linux it is the one whose name under /dev/serial/by-id ends in if01-port0. On Windows it is the one Device Manager calls "Standard COM Port".

Test, beside Keying, keys the radio for a second, so you see it go to transmit and come back.

On the radio

A new FTDX101 ignores what the computer does on the serial ports. Open RADIO SETTING → MODE PSK/DATA → RPTT SELECT and change it from DAKY, the RTTY/DATA jack on the back, to RTS. The other value is DTR.

The item exists once for each mode, so change the one of the mode the radio is in. In the DATA mode that is MODE PSK/DATA; for USB or LSB the same item is under MODE SSB.

To key by VOX instead, set Keying to VOX in NeoAPRS. It worked too, but RTS is the more dependable of the two.
