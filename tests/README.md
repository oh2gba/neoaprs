# The tests

`scripts/check --fast` runs everything; `.venv/bin/pytest -q tests/test_x.py` runs one file; `-m unit`, `-m integration`, `-m safety` pick a kind. `asyncio_mode = auto`: an `async def test_*` just works.

## What is here

* `test_architecture.py`, `test_size_ratchet.py`: the layers and the size limits (`docs/ARCHITECTURE.md`); each rule is shown failing on a made-up tree.
* `test_docs.py`, `test_hygiene.py`: the documents (the index, the names they put in backticks), the scripts and units tables (the unit is `neoaprs/cli/neoaprs.service`), `.gitignore`.
* `test_tnc.py`: the TNC source on a fake radio (a TCP server on the loopback): the live capture decodes, a TNC found in command mode is switched to KISS, the check when a line opens, the reopen of a line that was lost, a port given as `tcp://`, the keep-alive that a TCP KISS profile does not have, no search where the ports are not searched, sending, the mode detector and its re-arm, and the keep-alive (a quiet line gets the check after `check_sec`, with the exit frame, the carriage return and KISS ON in order and nothing sent meanwhile; a `cmd:` answer keeps it connected and tells nothing; no answer makes it silent with one warning; no check while packets or noise flow; `check_sec` 0, a new period, enter KISS off; a stop in any step leaves nothing running; a lost line starts the quiet period over).
* `test_tncprofile.py`: the TNC profiles (`neoaprs/tncprofile.py`): the table and the strings of each, the entry written step by step with its pauses (the TM-D710's five steps, the Kantronics, the TNC-2's one), the keep-alive check that enters again with the whole sequence, the `kiss` and `kiss-tcp` profiles that are sent nothing but KISS frames (no entry, no check, no carriage return, no silent state, not in the search of the ports either), and the settings that make the port: `tcp/host` and `tcp/port`, the `tnc/enter_kiss` row.
* `test_tnc_pty.py` (POSIX only): the search for the radio among device files, on pseudo-terminal pairs behind the globs of a pattern: the probe picks the port that sends KISS frames, skips one it cannot open or that another program holds or that is on the skip list, takes a TNC in command mode, sends the carriage return, ends with a stop, the fall back from a named port, a device file that vanishes and comes back, and the settings' pattern, the remembered port and the search after a remembered port is gone with the whole daemon.
* `test_silent.py`: the silent radio: a check that nothing answers makes the Tnc silent (the describe text, the lines, the log), command-mode text, a KISS frame or other bytes while silent end it cleanly (KISS entered afresh once for every answer, `usable` False until the settle has passed, one INFO line), the probes (answered at the return, answered after KISS ON, a hundred unanswered ones with one WARNING and no INFO, every 5th reopening the port and the silence kept across it, a lost line; the failed reopen falling to the search is in `test_tnc_pty.py`), a stop while probing leaves nothing running, a beacon due in the night written only after the settle as a KISS frame, and `beacon_now` and `send_message` refused over the socket with the reason; the senders' own cases are in `test_beacon.py`, `test_rigstatus.py`, `test_queries.py` and `test_messaging.py`.

## Windows

The suite runs on Windows in CI (`.github/workflows/ci.yml`; the Windows installer, the install script and the wheel are tried by `.github/workflows/release.yml`, not by the suite, `docs/MANUAL.md` "Releases"; `docs/MANUAL.md` "Continuous integration and the smoke test"). What is POSIX only carries `posix_only` (`support/ptyline.py`: a test, or `pytestmark = posix_only` for a file) and is skipped there: pseudo-terminals and device files (`test_serialport_pty.py`, `test_tnc_pty.py`), `/proc`, file modes, the shell scripts (`test_scripts.py` wrappers, `test_install.py`), the checks of the repository (`test_docs.py`, `test_hygiene.py`, `test_dup_check.py`) and the radio guard on `/dev` paths. `FakeTools` and `install_fake` skip themselves on Windows (their programs are scripts with a shebang). The rest is written for both systems:

* a daemon started as a process gets `creationflags=NEW_GROUP` and is stopped by `stop(proc)` (`support/proc.py`): SIGTERM on POSIX, Ctrl+Break on Windows, where `terminate()` is a kill and the exit code is not 0;
* the alert tests use `support/alertcmd.py`, the same few commands as a shell line and as PowerShell, with the longer waits a runner needs to start PowerShell;
* a refused connection is `REFUSED` (`support/fakeradio.py`), worded by the system and slow to come on Windows, so the tests wait for the state rather than for a time;
* files are read as UTF-8 (`read_text(encoding="utf-8")`; the default on Windows is cp1252);
* the leak guard does not count the tasks the Windows loop itself keeps for a listening server.

`mypy --platform win32` runs on the Linux job, so a POSIX-only call in `neoaprs/` has to say so (`# type: ignore[attr-defined, unused-ignore]` or a `sys.platform` branch).

## Markers

Every test is exactly one of `unit` (pure code, no loop, no daemon, no socket), `integration` (a loop, the Controller, a fake service, a child process) and `e2e` (a browser, when there are browser tests), given by `support/markers.py` from what the test uses, not by decorators.
`safety` is added to the tests of the data layer. `expects_errors` is set by a test that makes the code log an ERROR on purpose.

## The four guards

`support/guards.py`, wired in by `conftest.py`, run for every test:

1. **Nothing leaves this machine.** HOME and the XDG folders are an empty folder of the test; a connect, a datagram or a name lookup to an address that is not on the loopback fails the test, even when the code under test swallowed the error. Not even this machine's port 4532 or 4533 may be reached (the rigctld and rotctld of whoever runs the tests, on a real radio): a test that wants a radio starts a fake rigctld on a free port (`support/fakes.py`).
2. **No leak.** A test that ends with an asyncio task still running, or with the thread of a `Db` still running, fails. `support/env.py` stops the daemons of the `Env`s and closes the `Db`s of the stores the test opened (`support/storedb.py`).
3. **No unexpected ERROR.** A test that makes the code log an ERROR it did not say it expects fails.
4. **Never the radio.** A test that opens a path matching `/dev/brainbox_*` or `/dev/tty*` (through `serial.Serial` or `os.open`, symlinks resolved) fails: the tests use a fake radio on the loopback (`support/fakeradio.py`) and, for the few that are about a device file, a pseudo-terminal pair (`support/ptyline.py`, POSIX only).

A fifth thing that is not a guard but behaves like one: the logging (levels, handlers, switches) is put back as it was when the test ends.

## Properties

Hypothesis is in the `dev` group. `HYPOTHESIS_PROFILE=ci` (the default) is derandomised and keeps no example database, so a run is reproducible; `HYPOTHESIS_PROFILE=dev` explores with a random seed and 2000 examples. The properties of KISS, AX.25 and the APRS coders are `test_properties_kiss.py`, `test_properties_ax25.py` and `test_properties_aprs.py`.

## Order

`NEOAPRS_TEST_ORDER=reverse` or `shuffle:SEED` runs the test files in another order (the tests of a file stay in theirs): a test that only passes because of what an earlier file left behind fails in one of the two.
